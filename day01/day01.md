# 进制
**有符号视角的分界线**：8 位里 `0x00~0x7F` 是 0~127，`0x80~0xFF` 是 -128~-1。**0x80 是最小负数 -128，0x7F 是最大正数 127**—— 所以 `0x7F + 1 = 0x80` 这一越线，在有符号眼里就是 127 瞬间变 -128，这正是以后 D1 实验里 `OF=1` 的由来。

再看逆向里的真实场景：32 位程序里 `0xFFFFFFFF` 无符号是 4294967295，**有符号就是 -1**。以后读反汇编看到一串 F，第一反应就该是 “-1”。记住三组基准：8 位 `0xFF` / 16 位 `0xFFFF` / 32 位 `0xFFFFFFFF` 全是 -1。

# 数据宽度
| 宽度 | 位数 | 汇编伪指令 | C 类型（32 位） | 无符号范围 |
| --- | --- | --- | --- | --- |
| byte | 8 | `db` | char | 0~255 |
| word | 16 | `dw` | short | 0~65535 |
| dword | 32 | `dd` | int | 0~4294967295 |
| qword | 64 | `dq` | long long | 0~2⁶⁴-1 |


 每加 1 位，容量翻一倍。滴水的主战场是 **32 位 dword**——`EAX` 就是 dword，`AX` 是 word，`AL/AH` 是 byte。**以后看指令就知道宽度**：`mov eax, x` 读写 4 字节、`mov ax, x` 读 2 字节、`mov al, x` 读 1 字节。  

但换宽度就要重新看符号位：

0xFF 当 byte 看：无符号 255、有符号 -1；

0xFF 当 word 看：其实补成 0x00FF，符号位是 0，所以无符号、有符号都是 255；

0x8000 当 word 看：无符号 32768、有符号 -32768（负半区起点）。

# 四大家族（32 位）：
+ **EAX**：累加器，**函数返回值常放这**—— 以后读代码先看 EAX，就能猜到函数返回了什么；
+ **EBX** 基址、**ECX** 计数（循环 / 字符串指令）、**EDX** 数据（乘除法的余数落这）；
+ **ESI/EDI**：源 / 目的变址（memcpy 就是它俩 + ECX 干活）；
+ **EBP/ESP**：帧指针 / 栈顶指针 ——D3 栈帧的主角，先认名字。

**嵌套结构**：`EAX`（32 位）→ `AX`（低 16 位）→ `AH`（高 8）+ `AL`（低 8），EBX/ECX/EDX 一族同构。

```python
mov eax, 0x12345678
mov al,  0xAA
→ eax = 0x123456AA      ; 只有最后 1 个字节变了

```

# 标志位
| 标志 | 名字 | 置 1 条件 |
| --- | --- | --- |
| ZF | 零标志 | 结果 = 0 |
| SF | 符号标志 | 结果最高位为 1（有符号视角为负） |
| CF | 进位标志 | **无符号**视角溢出（进位 / 借位） |
| OF | 溢出标志 | **有符号**视角溢出（符号翻转） |


核心就一句：**CF 管无符号边界，OF 管有符号边界**—— 都是 “溢出”，两条边界各管各的。ZF 和 SF 简单，CF/OF 才是要反复品的。
